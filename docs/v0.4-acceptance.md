# v0.4 验收清单

本文件是发布检查表，不以文档中的勾选替代 CI 结果。除非条目明确说明，勾选只表示
对应测试已经存在，不表示所有 payload 类型、重放组合或 backend 矩阵都已穷尽验证。

- [x] dataclass、TypedDict、Pydantic v2 payload 的 schema identity 与严格 unit decode。
- [x] Pydantic v2 typed Worker 成功、nested model / optional null、poison DLQ 与 schema-version 不兼容的 SQLite/Redis 对称验证。
- [x] `submit_many(atomic=True)` 的批量原子性，以及 `atomic=False` 的逐项、同序结果和失败隔离。
- [x] typed DLQ replay，payload override schema 更新、旧 schema 清除及 queue payload size 校验。
- [x] v0.3 replay 兼容性：`payload=None` 保留原 payload/schema；`replace_payload=True, payload=None` 是唯一的 JSON null override。
- [x] DLQ/EQ replay keep/remove/replace、target queue、repeat replay 与 dedup-conflict rollback 的 SQLite/Redis 矩阵。
- [x] Admin inspect、CLI JSON/redaction/confirmation，输出 backend、namespace、queue；health 标为 connectivity probe。
- [x] SQLite 与 Redis URL CLI inspect/health smoke，Redis 使用隔离 namespace。
- [x] TaskBroker Protocol 与 `payload_type` API 对齐；类型检查不通过无意义 cast 伪装 backend 契约。
- [x] Redis 的 submit、claim、finish、lease extend、PEL recovery、maintenance 与 replay Lua 已全部迁至具名脚本模块；静态参数契约和 Redis lifecycle 回归测试已覆盖。
- [x] SQLite batch 提交具备可重复的本地 wall-time benchmark；Redis `submit_many()` 以 spy 测试证明单次 `EVAL`，少于相同数量的逐条提交 round-trip。
- [x] Redis conformance 与 replay matrix fixture 均清理随机 namespace；SubmissionService 与 SQLite Store 以内部 Protocol 表达稳定 backend 依赖。
- [x] README、operations、migration、CHANGELOG 和该验收材料说明 capability、风险与升级路径。
- [x] 从构建出的 wheel 在隔离环境执行 `taskqx --json health`，确认包内 CLI entry point 可用。

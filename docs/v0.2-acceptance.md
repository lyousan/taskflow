# Taskqx v0.2 验收清单

当前实现的 v0.2 验收范围如下：

- [x] Worker 固定并发、自动 ACK、优雅关闭和取消恢复；
- [x] `RetryPolicy` 的立即、固定、指数退避、上限、jitter 和异常分类；
- [x] Worker heartbeat；
- [x] `submit(delay=...)` 与 `delivery.retry(delay=...)`；
- [x] SQLite `DELAYED` / `available_at` 持久化和重启恢复；
- [x] Redis delayed Sorted Set、Lua 原子转移和重启恢复；
- [x] delayed 与 `expires_at` 联动并进入 EQ；
- [x] 消息上限与 Worker 策略上限取较小值；
- [x] SQLite / Redis Worker 行为和底层生命周期测试；
- [x] PEP 561 `py.typed` 类型包标记；
- [x] README、操作说明和 v0.1 迁移说明。
- [x] SQLite / Redis 共享行为契约测试（`tests/conformance/`）。
- [x] Worker 与 Consumer/Delivery backend 组件分层，backend 共享时间/ID 辅助模块。

## 非目标

v0.2 不承诺 Redis Cluster。Redis backend 的原子 Lua 路径仅保证 standalone / Sentinel
部署；Cluster 支持需要独立的 key-slot 设计与后续版本验收。

延迟调度采用按需 maintenance，不是后台自动调度器。生产部署应显式运行 maintenance
loop，或确保队列持续有 claim / inspect 活动。

# Taskqx v0.3 验收清单

- [x] `QueueConfig` 支持 max_attempts、lease、可选 retry_policy、default_dedup_ttl 和 max_payload_bytes。
- [x] 单次 submit/worker 参数 > queue 配置 > broker 默认值，且配置启动时校验。
- [x] SubmissionStore 可按 queue profile 路由，profile 与 capability 均可查询；混合 profile 的 batch 会预检拒绝。
- [x] 自定义 Store 只依赖 `PreparedSubmission`，不依赖 Broker 隐藏回调。
- [x] queue、namespace、profile 共享严格命名校验，并提供显式 legacy-name 读取模式。
- [x] 标准 `EventSink`/`TaskqxEvent` 与可选 `GaugeMetricsSink` 可注入，异常隔离。
- [x] submitted、duplicate、claimed、ack、retry、dead_lettered、expired、due、reclaimed 与 PEL recovery 事件包含稳定字段。
- [x] SQLite / Redis 在 claim 或 extend_lease 发现 expiry 时，先原子转入 EQ，再恰好发布一次 `expired` / `expired_total`。
- [x] Redis 以 server `TIME` 为时间权威；文档规定 NTP 同步，启动时对至少 5 秒的时钟偏差告警。
- [x] `SerializerRegistry` 按 name/version 解码，缺失 serializer 抛出 `SerializerUnavailableError`。
- [x] SQLite 与 Redis backend 行为测试、lint、类型检查和构建通过。

## 兼容性

v0.2 的 `BrokerEvent` 构造器、字段顺序和 `.name` 保持兼容；新 EventSink 代码应使用
`TaskqxEvent.event_name`。没有配置 `queues` 时，原有 broker 默认策略和低层
Consumer/Delivery API 保持不变。

# v0.6 验收清单：TUI 与交互式 CLI

> 本清单是开发计划；条目在实现并通过验证后才标记为完成。

## 打包与兼容

- [ ] `taskqx[tui]` 为可选 extra；基础安装不导入或依赖 Textual / prompt_toolkit。
- [ ] `taskqx tui`、`taskqx shell` 可发现；未安装 extra、非 TTY 和不支持的终端均给出明确提示及非零退出码。
- [ ] v0.5 的 Python API、`taskqx` 非交互子命令、JSON 格式和危险操作确认语义保持兼容。
- [ ] TUI 不写 SQLite schema、Redis keyspace 或 Consumer Group；启动与退出不影响外部 worker。

## 观察与浏览

- [ ] Health 首页正确显示 SQLite 与 Redis 的 health report、错误、warning、脱敏连接信息和刷新时间。
- [ ] 队列列表和消息/DLQ/EQ 列表均为分页 API；大数据量测试证明 UI 不进行无界读取。
- [ ] SQLite 与 Redis 具有相同的公开列表/详情语义，或通过 capability 和 UI 明确不支持的 filter。
- [ ] 消息详情包含状态、attempt、时间、失败原因和 serializer/schema；payload 默认 redacted。
- [ ] 显示 payload 需要显式操作；payload、Redis 密码和完整 dedup key 不写入 UI 日志或命令历史。
- [ ] 自动刷新只调用严格只读 API，不隐式执行 maintenance 或改变消息状态。

## 交互

- [ ] TUI 支持键盘导航、帮助、刷新、搜索、命令面板、窄终端布局和无色终端降级。
- [ ] REPL 支持 history、Tab 补全、`help`、上下文 prompt、命令错误建议和 JSON 输出。
- [ ] Tab 补全和搜索有页大小/请求次数边界，断连或权限失败时不会冻结界面。
- [ ] TUI/REPL 调用失败显示 backend 错误、可恢复建议和适当的退出状态；不静默吞错。

## 受保护操作

- [ ] DLQ/EQ replay 和删除展示消息、源/目标队列、dedup 策略及影响摘要，并要求二次确认。
- [ ] consistency repair 首先展示 dry-run；实际 apply 要求独立二次确认。非交互 CLI 继续要求 `--apply --yes`。
- [ ] replay 完成只报告 `replay_enqueued`，明确业务 handler 结果是异步的；回归测试覆盖“重新投递后再次 DLQ”的展示。
- [ ] 所有写操作仅调用公开 Admin API；测试证明 TUI/REPL 不直接拼 Redis key 或执行 SQL 状态迁移。

## 质量与文档

- [ ] SQLite 和 Redis 的 TUI/REPL smoke、断连、取消、分页、payload redaction 与危险操作测试齐全。
- [ ] 自动刷新 task 在退出、异常和 Ctrl-C 时被取消，broker 连接被关闭。
- [ ] 更新 README、operations、CLI help、v0.5→v0.6 迁移说明和 SQLite/Redis 示例。
- [ ] `ruff check`、mypy、全量 pytest（含 Redis integration）和 wheel 安装后的入口 smoke 均通过。

4. Redis TUI/REPL smoke、断连/取消、payload/history 泄露、危险操作和“replay 后再次 DLQ”的回归测试；
5. 在真实 TTY 且未安装 `taskqx[tui]` 时的缺失 optional dependency 提示测试。
